# 初始化项目指令文件时注入用户全局规则

在使用 Claude Code、Codex、DeepSeek Harness、Pi、WorkBuddy、Cursor、Trae、Qoder 等 Harness 工具执行 init 操作或初始化项目时,执行本 skill:向项目根目录的 **AGENTS.md**(该工具约定用 CLAUDE.md 的则写入 CLAUDE.md;两者都支持时优先 AGENTS.md)注入用户的两条全局硬性规则——【精炼回复】回复风格、删除安全(回收站)规则,即下面"注入内容"一节。

## 执行步骤

1. 检查项目根目录是否已有 AGENTS.md / CLAUDE.md(按工具约定选目标文件)。
2. 没有 → 创建并写入"注入内容";已有 → 把缺失的规则**合并**进去,不覆盖、不删除原有内容;规则已存在但表述旧 → 更新为下述最新版本。
3. 注入的是项目级规则,写到项目根目录的指令文件;不要动用户主目录的全局文件,除非用户明确要求。

## 注入内容(逐字使用)

```markdown
## 回复风格(用户硬性要求)

凡是包含方案/建议/分析的回答,结尾必须追加一段 **【精炼回复】**,格式硬性要求:

1. 先输出一行 Markdown 分割线 `---`,紧接 **【精炼回复】** 标题;
2. 内容结构化,加粗小标题+短列表,禁止一大段文字:「结论」一两句话;「主要事项」逐条一行;
3. 决策项结构化:每个问题独立成块,问题单独一行加粗,下面每个选项各占一行(列表),标注推荐项,不抛开放性问题;
4. 口吻像下级向上级汇报:通俗直白、先结论后理由,最大化节省用户的阅读时间、理解成本和决策成本。

## 删除安全规则(用户硬性要求)

- 批量整理、删除前,先列清单向用户确认,得到明确同意后再执行。
- 执行删除时不直接删除:把文件移到项目根目录的回收站文件夹(默认 `_recycle/`,项目已有约定则从约定),保持目录结构原样,便于随时恢复。
- 每个被删除的文件配一个 `<文件名>-delete reason.md`,写明:删除理由、原始位置、删除日期。
```

## 注意事项

- 向用户汇报注入结果时,说明写入了哪个文件、注入了哪几节。
- 回收站文件夹本身的用途,建议在注入时顺带写一行注释,避免后续 agent 把 `_recycle/` 当垃圾清掉。
